# 后宫 C 区交接

## 开工基线

- 计划、参考图、`STYLE_GUIDE.md`、`CONTRACTS.md`、`config.js` 与 `layout.js`：风格和接口 `v1`。
- 可写文件仅为 `src/zones/inner-palace.js` 与本交接文件；共享布局、建筑库、入口和其他区域保持只读。
- 全局坐标边界：`X ∈ [-100, 100]`，`Z ∈ [83, 302]`；Y 向上，南向建筑正面朝 `-Z`。
- `root` 使用单位变换；建筑均由 kit 注册，稳定 ID 前缀为 `inner-`。

## 区域范围与连接

内廷由三座沿中轴递进的围合庭院组成，分别位于 `z=115`、`184`、`255`。每座庭院登记南北中轴门和东西侧门，院墙与门洞由共享 `kit.makeWall` 构件组成，铺地使用 `kit.materials.ground`。

本区导出以下布局连接，坐标和宽度直接取自共享 `CONNECTORS`：

| ID | 坐标 | 连接区域 | 用途 |
| --- | --- | --- | --- |
| `axial-inner` | `[0, 0, 83]` | 前朝 | 内廷南入口 |
| `inner-garden` | `[0, 0, 302]` | 御花园 | 北侧御苑内门 |
| `west-north` | `[-104, 0, 180]` | 西宫苑 | 中庭西门道 |
| `east-north` | `[104, 0, 180]` | 东宫苑 | 中庭东门道 |

`layout.js` 将以上点列入共享连接表，但未显式写出连接点由哪一侧创建。本区只提供自身门道、道路和连接记录；相邻区沿相同连接 ID 对齐，不扩大冻结边界，也不另造边界门。

## 建筑与接口交付

- 18 栋可识别建筑，全部通过 `kit.addBuilding` 登记：内廷门、寝宫仪门、后寝垂花门、御苑内门、3 座主殿、寝殿东西配房、前后院配房、后寝亭及东西侧房。
- 3 座登记庭院：`inner-court-south`、`inner-court-middle`、`inner-court-north`。
- `inner-core-bedchamber` 登记为 `可入内（寝殿内景）`，保留 kit 的石台基、屋顶、踏步，以共享材质搭建开放式寝殿内景、床榻、柱与屏风；寝殿比例较前朝主殿收敛。
- 模块返回 `root`、`buildings`、`courtyards`、`connectors`、`update(dtSeconds, elapsedSeconds, state)`、`dispose()`。自建铺地和内景几何在释放时单独 dispose；不释放 kit 的共享几何、材质或资源。
- 所有屋面、墙体、门殿、树木、灯和材料均来自共享 kit；区域仅为庭院铺地、门殿开敞框架及一处内景制作局部几何，没有新建材质。
