## 2. 色彩 ↔ 材质 ↔ 构件对应

> **表中 `roughness` / `metalness` / `clearcoat` 均为「基础值」**：渲染时由材质库统一叠加旧化偏置
> `config.WEATHERING.roughnessBias = 0.04`（实测 `WEATHERING.roughnessBias === 0.04`，见 `src/kit/materials.js`），
> 因此**屏幕上的实际粗糙度 = 表中值 + 0.04**。实现方照表复刻时若不叠加，会与原库对不上（OBS-1，t20 记录）。

| 色板（`config.COLORS`） | 值 | 用途 | 材质 role（`config.MATERIALS`） | 光泽规范 |
| --- | --- | --- | --- | --- |
| 琉璃金 `glazeGold` | `#dfa112` | 主要屋顶瓦面、脊 | `glazeTile` | roughness 0.42 / metalness 0.06 / clearcoat 0.55（"有清漆感的非纯金属"） |
| 鎏金 `gilt` | `#ffc83b` | 宝顶、脊兽、门钉、铜器 | `giltMetal` | roughness 0.24 / metalness 0.92（**只有鎏金才有明显金属反射**） |
| 宫红 `palaceRed` | `#962822` | 墙身、柱、门扇 | `plasterRed` | roughness 0.78 / metalness 0（哑光） |
| 青绿彩画 `paintingTeal` | `#1c4e40` | 梁枋彩画、斗栱 | `paintingTeal` | roughness 0.66 |
| 暖白石 `warmWhite` | `#f0ece1` | 台基、栏杆、丹陛 | `stoneWhite` | roughness 0.62（温润，无镜面感） |
| 深灰铺地 `pavingGray` | `#575652` | 广场、道路铺装 | `pavingStone` | roughness 0.86 |
| 室内金砖 `interiorBrick` | **`#4a463f`**（物理反照率修正，`CONFIG 1.0.5`/t40；原值 `#1a1917` 为时点记录） | 金銮殿/寝殿室内地面 | `interiorBrick` | roughness 0.35 / clearcoat 0.35 |
| 木作 `timber`（派生） | `#7a3b24` | 木构、门窗框 | `timberLacquer` | roughness 0.55，轻微纹理 |
| 水面 `water`（派生） | `#33544f` | 护城河、水池 | `waterSurface` | roughness 0.08，反射适度、低饱和，不抢主体 |

> **金砖为何偏离计划表字面值（`CONFIG 1.0.5`，t40，主理人裁定）**：这是本表**唯一**偏离计划 §3.1 字面十六进制的项，依据是**物理反照率**而非审美：
> `#1a1917` 的线性反照率仅 **0.0098（≈1%）**，**低于任何真实建筑材料**（真实抛光深色砖石/金砖通常 **5–8%**）。
> 后果是内景补光在「内容暗区 ≤30% 且高光截断 ≤5%」双约束下**无解**——t38 诊断：把夜间补光拉满能让 C 寝殿夜暗区归零，
> 但截断升到 **7.74%**（C）/ **6.36%**（B），均 >5%。
> 修正为 `#4a463f`（线性反照率 **0.0620**，逐通道 0.0685/0.0612/0.0497）后：
> 金砖仍是**深色磨光砖**（sRGB 亮度 0.276，远低于浅色瓷砖；`roughness 0.35 / clearcoat 0.35` 的磨光特征保留），
> 而内景六格中四格已在双约束内（C 寝殿夜 **26.08% → 0.00% 暗区、截断 0.28%**，余量 30pp）。
> 原值 `#1a1917` 作为**时点记录**保留于此，不删历史。详见 [`docs/handoff-config-1.0.5.md`](handoff-config-1.0.5.md)。
> 配套建议（交 core 复核）：反照率转正后，`src/core/environment.js` 的**内景补光系数**应按新反照率回调
> （夜间 1.5/0.7 → ≈1.0/0.42；夕照 5.4/2.3 → ≈2.4/1.05），否则夕照内景会因"补光 × 新反照率"过曝（实测 clip 12.97%）。

**旧化**（`config.WEATHERING`，全城同一套，不得各自加重）：总强度 `0.2`，檐口/墙脚积尘 `0.25`，雨痕 `0.15`，
石材变色 `0.18`，墙脚苔痕 `0.12`。

**植被**（`config.PLANTS`）：树冠只有 `roundedCone / domedSphere / layeredUmbral` 三种；统一低饱和 `0.34`；
尺度 `5.5 / 9 / 13.5m`；花树点缀占比 `0.12`（色 `#e8b7bd`）；微风幅度 `0.045rad`。
每区域树木数量见 `layout.VEGETATION`（F 花园 64、F 墙外 40、B 10、C 14、D 32、E 32），随机序列由 `rngSeed` 固定以便复现与截图比对。

## 3. 比例与形制（`config.MODULES` / `GRADES` / `ROOF_TYPES`）

| 构件 | 数值 | 说明 |
| --- | --- | --- |
| 开间模数 | 面阔 `6.4m` / 进深 `5.2m` | 同类建筑共用；主次靠 `bays` 与 `grade` 区分 |
| 柱径 | `0.78m`（柱础 `0.92m`） | 不得逐栋随意调整 |
| 檐高 | `4.6m`（单层柱头→檐口） | 乘 `GRADES.grade.eaveHeightFactor`（1: 0.78 / 2: 1.0 / 3: 1.35） |
| 飞檐 | 出檐 `2.4m`、起翘 `0.55m`、弧度系数 `0.32`、角部起翘 `1.05m` | 同类建筑弧度一致 |
| 屋面 | 举架坡度 `0.55`、每间增量 `0.42`、瓦面厚 `0.42` | 形成凹曲屋面，禁止直板屋顶 |
| 台基 | 主殿三层共 **4.5m**（单层 1.5m、每层内收 9m）；其他 `0.4–2.0m` | 见 `layout.TERRACES`、槽位 `terraceH` |
| 台阶 | 单级高 `0.15m` / 深 `0.34m`，单跑 ≤20m | 与第一人称台阶阈值 `0.5m` 兼容 |
| 宫墙 | 厚 `8m`、高 `12m`、压顶 `1.1m` | 内表面贴包络，向外扩展（见 §4） |
| 院墙 | 厚 `1.2m`、高 `4.2m` | 每个院落四面墙由 `layout.WALLS` 生成，自动开门洞 |
| 廊道 | 宽 `3.6m`、柱距 `3.2m` | 按段统计，**不计入建筑数量** |

**屋顶等级**：主殿 `doubleEaveHip`（重檐庑殿，必须有长正脊与四面坡，禁止用尖顶替代）；次级 `hip / gableHip`；
院门、值房 `gable`；亭与角楼 `pyramidal / gableHip`。

`GRADES[grade].roofTypes` 给出该等级**允许**的屋顶类型白名单，kit 必须校验；每个槽位还必须同时满足
`roofType` 是 `config.ROOF_TYPES` 的合法键（`CONFIG 1.0.1` 起由 `tests/layout.test.mjs` 的"等级-屋顶白名单"
断言逐槽位 + 汇总机器拦截）。当前白名单：

| grade | 允许的 roofType | 说明 |
| --- | --- | --- |
| 1 | `gableHip`、`gable`、`pyramidal` | 侧院配房、院门、次级亭 |
| 2 | `doubleEaveHip`、`hip`、`gableHip`、`pyramidal` | 殿堂与门殿；`pyramidal` 用于**御花园中央主亭**（grade 2 + 攒尖顶，保持与 9 个次级亭的主次层级） |
| 3 | `doubleEaveHip` | 主殿与城门楼等最高等级，仅重檐庑殿 |

**高度语义**：`layout` 的 `eaveHeight`/`totalHeight` 是**估值**（非硬约束），几何真值以 kit 举架公式 +
`config` 令牌为准；取景、信息面板与验收脚本必须使用实测场景包围盒，详见 `docs/CONTRACTS.md` §4.1。

**可进入与内景**：仅 `B-hall-main`（金銮殿）与 `C-hall-bed-main`（寝殿正殿）不可替代地提供内景；
其余建筑一律登记为障碍物并在信息面板说明"不可进入"。

## 4. 参考图索引与坐标约定

- 参考图：`assets/reference/palace-layout.png`（387KB）。
- 用途：确定空间关系与整体观感——高位斜俯视、中央礼仪轴线、多重宫门与庭院、金黄屋顶、灰白铺地、
  左右院落群、后部宫苑、点缀树木与水景。图中的游戏状态、资源数值、竖向菜单与可见文字**不构成功能或命名要求**。
- 坐标：单位米，Y 向上，X 向东，Z 向北，宫城地面中心 `(0,0,0)`，建筑正面朝南（`-Z`）。
- 包络：宫墙内 `X ∈ [-300,300]`、`Z ∈ [-450,450]`（`layout.ENVELOPE`）。仅 F 的墙/角楼/城门可向包络外突出 `18m`（墙厚 8 + 角楼半宽 10）；B/C/D/E 严格在包络内。
- 竖向：地坪**分区各自**取值（B 广场 `0`、C 后宫 `0.9`、D/E 侧院 `0.4`、花园 `0.5`、桥面 `0.8`、护城河水面 `-3.0`），
  只有主殿台基是 `4.5m`——**不得把全城地坪统一抬到 4.5m**（计划 §2.3）。
- 对比方法：同一机位、同一时辰、同一质量档截图对比；全城鸟瞰与区域近景两个尺度都要看。

## 6. 光照、时辰与质量档

三个统一预设（`config.LIGHTING.presets`）全城共享太阳方向、天空、曝光、色调映射（ACESFilmic）、雾与环境反射。
`CONFIG 1.0.2`（t19，主理人裁定）后的冻结值：

| 预设 | 中文 | sun | ambient | hemi | exposure | fogNear → fogFar | 实测定性 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `goldenHour` | 盛世金辉 | 2.35 | 0.42 | 0.50 | 1.00 | **1400 → 3200** | 全城机位（≈1222m）不再被雾洗白；`oblique` 实测均值 0.713、高光截断 0%（**均值超 0.6 上限，见下方"待裁定"**） |
| `sunset` | 落霞夕照 | 2.00 | 0.50 | 0.55 | 1.06 | **1400 → 3200** | 同上修正雾距；`oblique` 实测均值 0.600、高光截断 0% |
| `moonlitNight` | 寒月宫灯 | **2.00** | **0.80** | **0.65** | **1.35** | 420 → 1800（夜间保留暗色空气透视，未改） | 方案A（1.0.2）+ 宫灯上调（1.0.3）：`oblique` 内容均值 **0.1029**、内容暗区 **3.57%**；内景夜内容暗区 72.9% → **1.44%** |

- **宫灯承担内景/近景亮度**（`CONFIG 1.0.3`，t26）：`LIGHTING.lamps.intensity` **不可低于 12**（当前 `18`）、`distance` **不可低于 46**（当前 `60`）、
  `decay 2→1`（风格化线性衰减；`decay=2` 时 10m 外照度仅 1/100，室内无法照亮）；**硬约束不变**：实时灯 ≤8（medium 档 6）、
  宫灯不投影、仅 1 盏主方向光投影，§8.2 预算不变；更远处继续用发光材质替代。
- **内景补光通道**：`goldenHour.lampIntensityScale 0 → 0.45`、`sunset 0.35 → 0.6`（日/夕让宫灯有限参与室内照明，
  **不动全局曝光与建筑形制**）；夜间 `moonlitNight.lampIntensityScale = 1`（满强度）。
- **动态阴影**：只允许 **一盏** 主方向光投影；宫灯不投影。
- **质量档**（`config.QUALITY.tiers`）：`high/medium/low` 只影响渲染成本，**不改变布局与可走性**；`medium`（DPR 1）是预算参考档。
- **可读性与过曝判据**（口径与阈值见 [`docs/CONTRACTS.md`](CONTRACTS.md) **§12**（`v1.0.5`，t26 修订），V2 与后续调整共用）：
  固定口径 `1440×900 / DPR 1 / medium / ?ui=0&shot=1`；**暗区按内容掩码评估**（排除背景/天空像素后再算，整帧数字仅诊断），
  并按视角类别分档——**俯瞰/环绕类**（`oblique`/`iso`/`orbit`/`zone`）**内容暗区 ≤15%**，
  **低空/近景类**（`focus`/`fp`/`interior`/**`axis`**）**≤30%**（夜景近景与低空序列机位的深阴影属预期：
  `axis` 是低空贴地序列机位、画面以暗地面/暗屋面为主，与 focus/fp/interior 同类——依据见 CONTRACTS §12.2，
  **不是"不达标就改分类"**）；内容均值 俯瞰类 ≥0.10、内景 ≥0.04；**过曝以高光截断 ≤5% 为主判据**，
  整帧均值 ≤0.75 仅作诊断（`goldenHour` 均值 0.6654 / 截断 0.00% 据此**不构成过曝**）。
- 允许微调 `sunIntensity/ambientIntensity/hemiIntensity/exposure/fog*`，但**必须回到同一份预设里改并递增 `CONFIG_VERSION`**，
  同时重跑 `node scripts/shot.mjs --view=all --preset=all` 与 `--judge`，把 before/after 数字写进报告（范例见
  [`docs/report-night-calibration.md`](report-night-calibration.md)）。

> **已裁定并落地（t26）**：`goldenHour` 全城均值 0.6654 曾被「整帧均值 ≤0.6」判为过曝——判据已改为
> **高光截断 ≤5% 为主**、整帧均值降为诊断（≤0.75 提示）；该预设 clip 0.00%、暗区 0.80% ⇒ **不构成过曝**。
> 另：`axis`（夜，内容暗区 29.31%）经 t34 裁定归入**低空/近景类（≤30%）**——依据是机位性质（低空贴地序列机位），
> 非"不达标就改分类"，`CONTRACTS §12.2` 已写明；档位表可用 `node scripts/shot.mjs --classes` 复算。
> **日/夕内景 49%–66% 仍未通过**（`docs/handoff-config-1.0.3.md` §5），最小修法需 kit 提供可透光窗扇 / 内景补光灯位。

## 7. UI 规范摘要（完整实现归 G）

- 中文衬线标题（`Songti SC / Noto Serif SC`）、朱红印章（`#962822`）、暗金细线（`rgba(223,161,18,.45)`）、
  深色半透明面板（`rgba(26,25,23,.82)`）。
- 间距只取阶梯 `4/8/12/16/24/32px`；面板圆角 `4px`；触控目标 ≥`32px`。
- 过渡：镜头 `1.2s`、UI `180ms`；所有过渡时长取自 `config`。
- 视角切换器、时辰、质量为同一套控件规范；窄屏（<720px）保持可读可操作。
- 加载层与失败提示：由 t1 的 `index.html` + `src/shared/base.css` 提供结构与基础皮肤（`#loading-layer / #loading-stage / #loading-progress / #loading-error / #loading-retry`），
  G 负责状态驱动，不得另建第二套加载层。
