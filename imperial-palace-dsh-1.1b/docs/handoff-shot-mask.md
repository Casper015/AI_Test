## 1. 根因与修复

### 1.1 根因（t39 发现）
`decodePngStats` 的背景色取**量化桶左下角**：`bg = ((key>>10)&31)<<3 …`，再配 `--content-tol 6`。
dusk 真实天空 **(210,175,127)** 落在桶 **(208,168,120)**：g 方向比较上界 `168+6 = 174 < 175` ⇒ **差 1 个量化单位**，
所有天空像素被判为"内容" → 内容占比 100% ⇒ **遮罩静默失效**，暗区被约 70% 的明亮天空稀释，判据照常 PASS。

### 1.2 修复（三处）
| # | 修复 | 说明 |
| --- | --- | --- |
| 1 | 背景色 = **主桶及相邻桶（±1 bin）内真实像素的均值** | 不再取桶左下角；相邻桶合并覆盖"天空轻微渐变 / 抗锯齿 / 轻微过曝" |
| 2 | **自适应容差** `effectiveTol = clamp(max(--content-tol, ⌈天空离散度⌉+1), 6, 24)` | 用测得离散度而不是猜 |
| 3 | 边框环 / 顶部 6 行的占比按**颜色邻近度**（≤ effectiveTol）重算 | 与掩码判定同一把尺子；两道门（≥25% / ≥50%）仍防误判建筑为背景 |

**精确案例的前后判定（同一张 `docs/shots/t2-oblique-dusk.png`）**：

```text
修复前：内容像素 100.0%  ← 掩码失效（天空 (210,175,127) 被漏掉）
修复后：内容像素 30.0%  · 背景 rgb(210,175,127)@100%（容差 6、离散 ±1）  · 内容均值 0.2010 · 内容暗区 2.09%
```

## 2. 静默失效防护（本任务核心）

`decodePngStats` 现在返回 `mask` 诊断，**并在以下情况显式告警**；`--judge` 下**判 FAIL（非零退出）**——不再允许"掩码坏了却照常 PASS"：

| 触发条件 | 消息 | 备注 |
| --- | --- | --- |
| 存在背景候选，但内容占比 ≥ `--mask-max-content`（默认 0.98） | 掩码可疑：存在背景候选 rgb(…) 但内容占比 100.00% ≥ 98%（容差边界极可能失效） | 正是本次根因的特征 |
| 未识别到背景（外景且未加 `--allow-no-sky`） | 未识别到背景（边框/顶部无稳定主色）：判据按整帧计算，可能偏乐观 | **内景自动豁免**（内景本来无天空） |
| 背景占比 < `--mask-min-bg-share`（默认 0.05） | 背景占比过低：边框环主色仅 X% < 5% | — |
| 内容占比 ≤ 2% | 内容占比仅 X%：画面近似纯色/几乎全为背景，内容判据无意义 | 指标退化的另一种形态 |
